# 部署指南

覆盖本地开发与生产自托管两条路径，本指南只讲怎么跑起来、怎么运维。

## 1. 本地开发环境

### 1.1 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 25（Temurin） | 后端编译与运行 |
| Flutter | 3.47.x stable | 与 `pubspec.yaml` 环境约束一致 |
| Docker + Compose v2 | 任意近期版本 | 起 MySQL / Redis |

### 1.2 基础设施

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d mysql redis
```

首次使用先 `cp deploy/.env.example deploy/.env`，按需改口令。端口整体偏移（MySQL 13306、
Redis 16379）是为了避开本机已有实例；`JWT_SECRET` 必须填一个 ≥32 字节的 Base64 值，
生成方式：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### 1.3 后端

```bash
cd backend
./mvnw spring-boot:run    # http://localhost:8080，接口文档 /api-docs
```

宿主机直跑需要环境变量与 compose 暴露的端口对齐：

```bash
export DB_PORT=13306 DB_PASSWORD=<deploy/.env 里的 DB_PASSWORD> \
       REDIS_PORT=16379 REDIS_PASSWORD=<deploy/.env 里的 REDIS_PASSWORD> \
       JWT_SECRET=<32 字节 Base64>
```

或者在 IDE 里启用 `local` profile：复制 `backend/src/main/resources/application-local.yml.example`
为 `application-local.yml`（已被 gitignore 排除，不会入库）填值。集成测试读的是
`src/test/resources` 下的同名文件，两份互不影响。

### 1.4 Flutter 客户端

```bash
cd app
flutter pub get
flutter run    # 默认 API 基址 http://10.0.2.2:18088（Android 模拟器 → 宿主机 Nginx）
```

联调真机或直连后端时注入基址：

```bash
flutter run --dart-define=API_BASE_URL=http://<局域网IP>:18088
```

注意：release 构建必须显式传 `API_BASE_URL`，缺省会直接报配置错误而不是静默连模拟器地址。

### 1.5 Windows 开发机的已知约束

项目路径含中文时，`gen_snapshot`（release AOT）与 `build_runner` 无法读写该路径，先映射成
ASCII 盘符再进 `app/` 执行：

```powershell
subst X: "<项目所在的中文路径>"
X:
cd X:\app
```

### 1.6 测试

```bash
cd backend && ./mvnw -o verify        # 全量集成测试，依赖 1.2 起的真实 MySQL/Redis
cd app && dart analyze && flutter test
```

## 2. 生产部署（自托管，Docker Compose）

### 2.1 环境要求

一台 2C2G 起步的 Linux 服务器即可跑下全家桶（compose 已按 2C2G 调过内存参数）。
如果服务器上已有别的服务，先看这张表再动手：

| 服务器已有 | 家记要求 | 结论 |
| --- | --- | --- |
| JDK 8/11 | 后端按 Java 25 编译 | 后端容器化（`eclipse-temurin:25-jre-alpine`），不动宿主机 JDK |
| MySQL 5.7 | 迁移脚本用 `utf8mb4_0900_ai_ci`（MySQL 8+ 专属） | 另起一个 MySQL 8.4 容器，端口避开 3306 |
| Redis | 常规命令 | 可复用，配 `REDIS_HOST/PORT/PASSWORD` 即可 |
| Nginx | 反代 + `/photos/` internal 直出 | 可复用，加一个 server 段 |

端口规划：MySQL 8.4 → `127.0.0.1:3307`；后端 → `127.0.0.1:8080`（不对外）；Nginx 对外 → `18088`。

不需要复用现有 Nginx/Redis 的话，直接用仓库根目录的 `deploy/docker-compose.yml --profile full`，
四个容器全起，对外只暴露 Nginx 一个口。

### 2.2 目录与文件

服务器上建议建 `/opt/homeledger`：

```bash
cd /opt/homeledger
mkdir -p uploads        # 档案照片目录，app 容器与 nginx 共享
```

把 `deploy/prod/` 下四个文件放进来（git clone 或 scp）：`docker-compose.yml`、
`nginx-homeledger.conf`、`.env.prod.example`、`Dockerfile`（在 `backend/`，打包镜像用）。

### 2.3 配置

```bash
cp .env.prod.example .env.prod
vi .env.prod
```

必填：`DB_NAME/DB_USERNAME/DB_PASSWORD/MYSQL_ROOT_PASSWORD/REDIS_PASSWORD/JWT_SECRET`。
所有口令用强随机值，JWT_SECRET 生成方式同 1.2。`.env.prod` 不入库，泄露过一次就轮换。

### 2.4 起 MySQL 8.4 并确认健康

```bash
docker compose --env-file .env.prod up -d mysql8
docker ps --filter name=homeledger     # 等 healthcheck 变 healthy（首次拉镜像较慢）
```

首次启动 Flyway 自动建库迁表（含疫苗程序表、生长标准字典的种子数据）。

### 2.5 构建并启动后端

jar 必须在装有 JDK 25 的机器（开发机或 CI）上打：

```bash
cd backend
./mvnw -DskipTests clean package
# 产物 backend/target/backend-1.0.0.jar，名字随 pom <version> 走，与 Dockerfile 的 COPY 同步
```

传到服务器并构建镜像：

```bash
scp backend/target/backend-1.0.0.jar backend/Dockerfile root@<服务器IP>:/opt/homeledger/backend/
ssh root@<服务器IP>
cd /opt/homeledger/backend && docker build -t homeledger-backend:1.0.0 .
```

启动并验证：

```bash
cd /opt/homeledger
docker compose --env-file .env.prod up -d
docker logs -f homeledger-app          # 看到 "Started HomeledgerApplication" 即成功
curl http://127.0.0.1:8080/actuator/health
```

### 2.6 接入 Nginx

- 宿主机安装的 nginx：`deploy/prod/nginx-homeledger.conf` 放到 `/etc/nginx/conf.d/homeledger.conf`，
  `nginx -t && nginx -s reload`。
- docker 里的 nginx：挂载进容器相同路径并 reload，此时把 `proxy_pass` 改成后端容器地址
  （同网络用 `http://homeledger-app:8080`），`/photos/` 的 alias 指向容器内能看到 uploads 的挂载点。

验证：

```bash
curl http://127.0.0.1:18088/actuator/health    # nginx → 后端
curl http://127.0.0.1:18088/nginx-health       # ok
```

### 2.7 防火墙

只放行 Nginx 的对外端口（18088，或改 80/443）。8080、3307 已绑 `127.0.0.1`，不要放开。

## 3. 构建正式 APK

### 3.1 图标（一次性）

图标源图已按启动页设计生成好，接入一次即可：

```bash
cd app && flutter pub get && dart run flutter_launcher_icons
```

### 3.2 签名（一次性，务必备份）

```bash
cd app/android
keytool -genkeypair -v -keystore homeledger-release.jks -alias homeledger \
  -keyalg RSA -keysize 2048 -validity 10000 -storetype JKS
```

在 `app/android/` 新建 `key.properties`（已被 gitignore 排除）：

```properties
storePassword=<keystore 口令>
keyPassword=<key 口令>
keyAlias=homeledger
storeFile=homeledger-release.jks
```

keystore 丢了，已发布的 App 就无法再升级，务必备份到仓库之外的地方。

### 3.3 打包

Windows + 中文路径先按 1.5 subst，然后：

```bash
cd X:\app
flutter build apk --release --dart-define=API_BASE_URL=https://<你的域名或IP>:<端口>
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`。发新版记得递增
`pubspec.yaml` 的 `version: 1.0.0+n` 中的 `+n`（versionCode）。

### 3.4 在 CI 上出包

自建 CI（GitHub Actions、Gitea Actions 等）跑 `flutter build apk --release` 时注意两点：

1. 必须把 `API_BASE_URL` 作为构建参数传入，缺 `--dart-define` 的 release 包会在启动时直接
   抛配置错误（这是有意的，防止静默打出连不上后端的包）；
2. CI 里没有 keystore，产物是 debug 签名，只能自用。正式分发用 3.3 本地打，或把
   `homeledger-release.jks` 与 `key.properties` 作为 CI 密钥注入——**不要把 keystore 提交进仓库**。

## 4. 备份与恢复

`scripts/backup/` 下的脚本已参数化，默认面向开发 compose；生产用法：

```bash
cd /opt/homeledger
COMPOSE_FILE=deploy/prod/docker-compose.yml \
ENV_FILE=deploy/prod/.env.prod \
MYSQL_SERVICE=mysql8 \
UPLOADS_SOURCE=/opt/homeledger/uploads \
scripts/backup/backup.sh
```

- 数据库（mysqldump，`--single-transaction`）与照片目录**同时间戳成对**产出，恢复也必须成对；
- 脚本自带 gzip 完整性校验、失败清理半截产物、flock 防重入；
- 保留 31 天滚动（比解散家庭的 30 天物理清除多一天，两者不冲突）。

crontab 建议（每天 02:30，与后端 01:30 的物理清除任务错开）：

```
30 2 * * * cd /opt/homeledger && scripts/backup/backup.sh >> /var/log/homeledger-backup.log 2>&1
```

异地副本（强烈建议）：`rsync -a --delete /opt/homeledger/backups/ backup@offsite:/srv/homeledger-backups/`。

恢复：

```bash
scripts/backup/restore.sh <时间戳>    # 如 20260917-023000
```

流程是：自动先备份当前库（`mysql-pre-restore-*.sql.gz`）→ 停 app → 恢复数据库 → 恢复照片 →
起 app。恢复意味着放弃备份点之后的当前数据，脚本会要求二次确认。**没演练过的备份等于没有**，
上线后请完整走一次恢复流程。

## 5. HTTPS

默认 compose 是纯 HTTP，Bearer 令牌与密码明文过网，对外服务前务必接 TLS：

1. 域名解析到服务器，安全组放行 80/443；
2. certbot 签发并自动续期：`certbot --nginx -d <域名>`；
3. 80 全量 301 到 443，nginx server 段加 `add_header Strict-Transport-Security "max-age=31536000" always;`；
4. 客户端 `API_BASE_URL` 换成 `https://`；
5. `app/android/app/src/main/AndroidManifest.xml` 去掉 `android:usesCleartextTraffic="true"`，重新打包。

后端代码不用改（已支持 `X-Forwarded-Proto`）。

## 6. 升级

```bash
# 服务器
cd /opt/homeledger && git pull
cd backend && ./mvnw -DskipTests clean package      # 或开发机打好 scp 过来
cd /opt/homeledger/backend && docker build -t homeledger-backend:<新版本> .
cd /opt/homeledger
# 改 .env.prod 无需动；compose 里 image tag 同步后：
docker compose --env-file .env.prod up -d
docker image prune -f
```

Flyway 迁移在启动时自动执行。若迁移失败（如唯一索引撞上历史脏数据），看
`docker logs homeledger-app` 里 Flyway 报错定位到具体版本号处理。

App 端升级与后端**同版本发布**：客户端模型与后端响应结构是配套演进的，不要单独只升一边。

## 7. 日常运维

- 内存：compose 已钉 `mysql8 768m`（buffer pool 128M、关 performance_schema）、`app 1024m`
  （JVM 按 cgroup 自动压堆）。2G 机器建议补 2G swap 兜底：

  ```bash
  fallocate -l 2G /swapfile && chmod 600 /swapfile
  mkswap /swapfile && swapon /swapfile
  echo '/swapfile none swap sw 0 0' >> /etc/fstab
  ```

- 健康检查：`curl http://127.0.0.1:18088/actuator/health`；compose 的 healthcheck 会让
  unhealthy 状态在 `docker ps` 可见（Docker 本身不会因 unhealthy 重启容器，需要自动拉起
  就加 autoheal 类看门狗）。
- 日志：所有容器 json-file 上限 10m×3；`docker compose logs -f app`。
- 改过 compose 后应用：`docker compose --env-file .env.prod up -d`，**永远不要带 `-v`**。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端起不来，日志见 JWT 相关 IllegalStateException | `.env.prod` 的 JWT_SECRET 缺失或不足 32 字节 |
| 上传照片 413 | 检查 nginx `client_max_body_size`（10m）与后端 multipart 上限是否被改小 |
| 照片能传但显示 404 | `/photos/` 的 alias 路径与 uploads 挂载不一致，或 nginx 没共享该目录 |
| Flyway 报 `utf8mb4_0900_ai_ci` 相关错误 | 连到了 MySQL 5.7，确认 8.4 容器健康且 3307 端口没被占用 |
| Windows 打包报 gen_snapshot 路径错误 | 按 1.5 subst 后再执行 |
| 恢复后统计数据不对 | 确认 restore.sh 走完（它会重启 app 清缓存）；手动兜底 `docker restart homeledger-app` |
